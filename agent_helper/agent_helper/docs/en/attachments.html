Image attachments

Sending an image, extraction with a vision model and use in a plugin

The user can send an image with a message (e.g. a photo of an invoice). The core stores the image, extracts its data as JSON with a vision model, runs arithmetic checks and appends the extracted text to the message so the LLM can use it.

Sending#

JSON
{"message": "Register this invoice", "image": "data:image/jpeg;base64,/9j/4AAQ..."}
  • Formats: png, jpg, webp; at most MAX_UPLOAD_BYTES (5 MB by default).
  • Storage path: <UPLOAD_DIR>/<user_id>/<uuid>.<ext> in default_storage.
  • With an attachment the fast path is skipped and the plugins' attachment_tags are selected.

Events#

data: {"event": "tool_status", "status": "Reading the attached image..."}
data: {"event": "attachment_data", "data": {"seller": "...", "total": 23370000, "items": [...]}, "warning": ""}

If reading fails, an error event is sent; the message is stored but the LLM is not run.

Vision model configuration#

Python
AGENT_HELPER = {
    # default: the same LLM_* settings
    'VISION_BASE_URL': 'http://vision.internal:8000/v1',
    'VISION_MODEL': 'qwen2.5-vl',
    'VISION_TIMEOUT': 90,
}

Using it in a plugin#

The file path is stored in the user message content (message.content["attachment"]); a plugin can link it to domain data (for example save it in a form's file field). Write a prompt rule tagged for attachments telling the model to treat image values as the form source and to ask about unclear values.

Machine-read values

Image extraction can be wrong; always show the values in the preview card and leave execution to the button.
