Concepts and architecture

The life of a message, the plugin contract, data models and action statuses

Life of a message#

  1. Entry: POST chat/ with an authenticated user; rate limits (per minute / per day); the image attachment is stored if present.
  2. Image: if there is an attachment, the vision model extracts its data and the text is appended to the message (the fast path is skipped).
  3. Fast path: if enabled: conversation mode, route regexes, one light-model call, then the plugins' routes. It answers only with confidence ≥ threshold.
  4. LLM loop: conversation history + relevant tools + a prompt built from fragments; the model calls tools until the final answer (at most 6 rounds).
  5. Events: every step is sent as SSE; proposals produce a pending_action card.
  6. Execution: only when the user presses the button: POST actions/<id>/confirm/.
  7. Logs: one request log row + a log for every model and tool call.

Parts of the plugin contract#

PartRolePage
PluginBundles all parts of a plugin; registered with agent_helper.registerWriting a plugin
ToolSpecA tool the model or the fast path calls; read-only or proposalTools

Data models#

ModelPurpose
AssistantConversation (alias: Conversation)A conversation per user; mode = multi-step dialog state
AssistantMessage (Message)user / assistant messages; JSON content (text and attachment path)
PendingActionPending action: kind, payload, status, expires_at, result
ActionAuditLogAudit of each real execution: user, action, item id, status, detail
AssistantRequestLog (RequestLog)One row per message: path, reason, intent, call counts, tokens, duration
ModelCallLogEach model call (intent / chat / vision)
ToolCallLogEach tool run with arguments and a result summary

Pending action statuses#

StatusMeaning
pendingWaiting for the user's button (10 minutes by default)
confirmedExecuted
partialSome items were executed
failedExecution failed (or the executor raised)
cancelledThe user cancelled, or nothing was selected
expiredThe deadline passed; it can no longer be confirmed

Design principles#

  • The AI proposes, a human executes.
  • Everything is scoped to the current user.
  • Cheap and fast first, smart second; a confident wrong answer is worse than a slow one.
  • Traceable: every decision and call is logged.
