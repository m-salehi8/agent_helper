Pending actions (ActionKind)

The only way to change data: proposal, card, button, execution with lock and audit

Every data change happens only through a pending action: a tool creates a proposal, the UI shows a card, and only when the user presses the button is the execute of that action kind run.

ActionKind(kind, execute, preview=lambda payload: {}, propose_schema=None, audit_label='', expires_minutes=10, resets_mode=False)
ArgumentDescription
kindUnique name; stored in PendingAction.kind
executeexecute(user, action, params) -> dict; only from the confirm endpoint
previewpreview(payload) -> dict fields of the pending_action event (what the card shows)
propose_schemaJSON schema of the proposal; required keys are checked when proposing
audit_labelShort label in audit rows the core writes (e.g. execution errors)
expires_minutesLifetime of the proposal
resets_modeClear conversation.mode after a successful execution

Lifecycle#

  1. The tool calls ctx.propose(kind, payload) ⇒ a PendingAction row with status pending.
  2. The core sends the pending_action event = {event, action_id, ...preview(payload), expires_at}.
  3. The user presses the button ⇒ POST actions/<id>/confirm/ (any body, e.g. the ticked rows).
  4. Inside a transaction the core checks: row lock, ownership (403), idempotency (a repeat returns the previous result), status, expiry.
  5. execute(user, action, params) runs inside a savepoint.
  6. The core stores the final status, execution time and result.

execute return contract#

Return valueEffect
{"status": "confirmed" | "partial" | "failed" | "cancelled", "message", "results": [...], "status_code": 200}The action is finalised; results is stored in action.result
{"error": "...", "status_code": 400} (no status)The request is rejected but the action stays pending (e.g. invalid parameter)
ExceptionThe core audits it, marks the action failed and responds 500; no half-done change remains
Python
from agent_helper import actions
from agent_helper.plugins import ActionKind


def execute_cancel(user, action, params):
    order = Order.objects.select_for_update().filter(id=action.payload['order_id'], user=user).first()
    if order is None or order.status != 'open':                 # check again
        actions.audit(user, action, 'failed', 'Order is no longer open', node_id=action.payload['order_id'])
        return {'status': 'failed', 'message': 'The order can no longer be cancelled.',
                'results': [{'status': 'failed'}], 'status_code': 200}
    order.status = 'cancelled'
    order.save(update_fields=['status'])
    actions.audit(user, action, 'confirmed', 'Order cancelled', node_id=order.id, amount=order.total)
    return {'status': 'confirmed', 'message': f'Order {order.id} was cancelled.',
            'results': [{'order_id': order.id, 'status': 'success'}], 'status_code': 200}


CANCEL_ORDER = ActionKind(
    kind='cancel_order',
    execute=execute_cancel,
    preview=lambda p: {'kind': 'cancel_order', 'order_id': p['order_id'], 'total': p['total']},
    propose_schema={'type': 'object', 'required': ['order_id']},
    audit_label='Cancel order',
)

Audit#

actions.audit(user, action, status, detail='', node_id=None, flow_id=None, amount=None)

node_id = item id, flow_id = parent object, amount = amount (all optional). Write one row per item.

Proposing without a tool#

Python
from agent_helper import actions
action = actions.create_pending(request.user, conversation, 'cancel_order', {'order_id': 5, 'total': 1000})
event = actions.pending_event(action)      # the same SSE card event
Never

In execute, never trust params to choose the user or the object; accept only a subset of the same payload (such as ticked rows that were part of the proposal).
