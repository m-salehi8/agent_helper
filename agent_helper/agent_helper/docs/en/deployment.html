Deployment

Installing on an offline server, nginx, self-hosted models and installing on existing tables

Checklist#

  • Wheels and the wheelhouse on the server; pip install --no-index --pre.
  • migrate.
  • LLM, light-model and vision addresses in settings or environment variables.
  • A shared cache (Redis) for rate limits across processes.
  • nginx: no buffering for the chat/ path; read timeout ≥ 120 seconds.
  • An ASGI/WSGI server with enough workers: each LLM conversation holds a worker until the stream ends.
location /api/assistant/chat/ {
    proxy_pass http://app;
    proxy_buffering off;
    proxy_read_timeout 180s;
}

Self-hosted models#

  • LLM: vLLM or any OpenAI-compatible server with tool calling; LLM_PROVIDER='openai'. Prefix caching makes the repeated prompt tokens cheap.
  • Light model: Jev (or any server with the same /v1/systemone contract) or a small model with logprobs (INTENT_BACKEND='llm').
  • Vision: a VL model on the same server or a separate one (VISION_*).

After changing a model, re-run the routing evaluation and one full scenario per plugin.

Installing on existing tables (different label)#

If the tables already exist from an earlier version under another app label (e.g. assistant), without changing the database:

Python
# myproject/agent_apps.py
from agent_helper.apps import AgentHelperConfig

class AssistantConfig(AgentHelperConfig):
    name = 'agent_helper'
    label = 'my_old_label'      # same tables, content types, permissions and admin URL names

# settings.py
INSTALLED_APPS += ['myproject.agent_apps.AssistantConfig']
MIGRATION_MODULES = {'my_old_label': 'myproject.old_migrations'}   # the existing migration history
Manual migrations

In this setup makemigrations must only run for the old label. The package's own initial migration (agent_helper/migrations) is for fresh installs.

Upgrading#

Shell
pip install --no-index --find-links dist --pre --upgrade agent-helper
python manage.py migrate
python manage.py check
