Writing a plugin

Layout, registration and rules of a plugin

A plugin is an ordinary Django app that registers a Plugin object in AppConfig.ready(). The core knows nothing about the domain; all knowledge (tools, actions, prompt rules, fast routes) lives in the plugin.

Suggested layout#

myplugin/
├── apps.py          # register(PLUGIN) in ready()
├── models.py        # domain models (if needed)
├── plugin.py        # ToolSpecs, ActionKinds, PromptFragments, FastRoutes and PLUGIN
├── services.py      # domain logic (queries, validation, execution)
└── tests/

Plugin#

Plugin(name, tools=(), actions=(), catalogs=(), prompt_fragments=(), fast_routes=(), attachment_tags=())
FieldTypeDescription
namestrUnique name; registering again with the same name replaces the previous one
toolsToolSpec[]Tools; a tool name must be unique across all plugins
actionsActionKind[]Pending action types; unique kind
catalogsCatalogProvider[]Entity catalogs for the "which one?" question
prompt_fragmentsPromptFragment[]Prompt rules
fast_routesFastRoute[]No-LLM routes
attachment_tagstuple[str]Tags selected when the message has an image

Registration#

Python
from django.apps import AppConfig

class MyPluginConfig(AppConfig):
    name = 'myplugin'

    def ready(self):
        import agent_helper
        from myplugin.plugin import PLUGIN
        agent_helper.register(PLUGIN)

Plugins are ordered as in INSTALLED_APPS, which also orders their tools, routes and rules. manage.py check reports inconsistencies (agent_helper.E001: a proposing tool whose action kind is not registered).

Golden rules#

  1. A tool must never read a user id from its arguments; every query is filtered by the incoming user.
  2. A tool must never change anything; changes happen only in ActionKind.execute. A tool only calls ctx.propose().
  3. execute re-checks everything (the data may have changed since the proposal) and writes an audit row for every item.
  4. Keep tool output short and structured; the model builds its answer from it and the UI builds cards from its events.
  5. Treat text inside data (titles, notes) as data, not instructions; the core injection rule is always in the prompt.

Complete example#

The agent-helper-demo package (file agent_helper_demo/plugin.py) is a small but complete plugin: two read-only tools, one proposing tool with the add_note action, one fast route ("how many leave days do I have?") and one prompt rule, with tests.

Several plugins together#

Several plugins can be installed at once; the model sees the tools of all of them (or only the relevant ones with tool selection). Use distinct tags so that tool selection works well.
