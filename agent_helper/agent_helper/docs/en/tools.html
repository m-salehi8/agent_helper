Tools (ToolSpec)

Defining a tool, the handler, events and proposing tools

ToolSpec(name, description, json_schema, handler, read_only=True, proposes=None, tags=(), status=None, events=None, conversation_mode=None)
ArgumentDescription
nameUnique name ([A-Za-z0-9_-], at most 64)
descriptionText the model reads to decide whether to call it; keep it precise and short
json_schemaJSON schema of the arguments; must be {"type": "object", ...}
handlerhandler(user, args, ctx) -> dict
read_onlyTrue for reading. False means it creates a proposal and proposes is required
proposesThe action kind this tool proposes
tagsTopic tags for tool selection; an untagged tool is always sent
statusText (or callable(args)) of the tool_status event
eventscallable(result) -> [event, ...] extra SSE events (e.g. a table)
conversation_modeIf not None, sets conversation.mode before running

handler#

handler(user, args: dict, ctx: ToolContext) -> dict
  • user: the authenticated user of the request; never taken from the arguments.
  • args: the model's arguments (always a dict; may be incomplete or wrong — validate them).
  • ctx.conversation: the current conversation (or None when run directly).
  • ctx.propose(kind, payload, minutes=None): creates a pending action; the core sends the card itself.

Return errors as {"error": "..."} so the model can explain them to the user; an unhandled exception becomes a generic error.

Python
def get_order(user, args, ctx):
    try:
        order_id = int(args.get('order_id'))
    except (TypeError, ValueError):
        return {'error': 'order_id must be a number.'}
    order = Order.objects.filter(id=order_id, user=user).first()   # always scoped to user
    if not order:
        return {'error': 'Order not found or not yours.'}
    return {'id': order.id, 'status': order.get_status_display(), 'total': order.total}


GET_ORDER = ToolSpec(
    name='get_order',
    description="Details of one of the user's own orders by id",
    json_schema={'type': 'object', 'properties': {'order_id': {'type': 'integer'}}, 'required': ['order_id']},
    handler=get_order,
    tags=('orders',),
    status=lambda args: f'Fetching order {args.get("order_id")}...',
)

Custom events#

To make the UI show a table or a card, use events. The event name is free; the client must know it.

Python
def _orders_event(result):
    if not result.get('orders'):
        return []
    return [{'event': 'order_list', 'items': result['orders'], 'count': len(result['orders'])}]

ToolSpec('list_orders', '...', SCHEMA, list_orders, events=_orders_event)

Proposing tool#

Python
def propose_cancel(user, args, ctx):
    order = Order.objects.filter(id=args.get('order_id'), user=user, status='open').first()
    if not order:
        return {'error': 'You have no open order with this number.'}
    action = ctx.propose('cancel_order', {'order_id': order.id, 'total': order.total})
    return {'status': 'ready', 'action_id': action.id,
            'message': 'Cancellation draft is ready; tell the user to press the button. Never say it was cancelled.'}

ToolSpec('propose_cancel', 'Draft the cancellation of an open order (does not cancel)', SCHEMA, propose_cancel,
         read_only=False, proposes='cancel_order', tags=('orders',))
Multi-step dialogs

For forms that take several question-and-answer turns, pass conversation_mode='create' (or any other name). Until the mode is cleared, the user's short messages ("November 15") do not go to the fast path. Other tools clear the mode with conversation_mode='', and an action with resets_mode=True clears it after a successful execution.

from agent_helper import tools
