اقدام معلق (ActionKind)

تنها راه تغییر داده: پیشنهاد، کارت، دکمه، اجرا با قفل و ممیزی

هر تغییری در داده فقط از راه اقدام معلق انجام می‌شود: ابزار پیشنهاد می‌سازد، رابط کاربری کارت نشان می‌دهد و فقط وقتی کاربر دکمه را بزند، execute همان نوع اقدام اجرا می‌شود.

ActionKind(kind, execute, preview=lambda payload: {}, propose_schema=None, audit_label='', expires_minutes=10, resets_mode=False)
آرگومانتوضیح
kindنام یکتا؛ در PendingAction.kind ذخیره می‌شود
executeexecute(user, action, params) -> dict؛ فقط از endpoint تایید
previewpreview(payload) -> dict فیلدهای رویداد pending_action (آنچه کارت نشان می‌دهد)
propose_schemaJSON schema پیشنهاد؛ کلیدهای required هنگام پیشنهاد بررسی می‌شوند
audit_labelبرچسب کوتاه در ممیزی‌هایی که هسته می‌نویسد (مثلاً خطای اجرا)
expires_minutesعمر پیشنهاد
resets_modeبعد از اجرای موفق conversation.mode پاک شود

چرخه‌ی عمر#

  1. ابزار ctx.propose(kind, payload) ⇐ ردیف PendingAction با وضعیت pending.
  2. هسته رویداد pending_action = {event, action_id, ...preview(payload), expires_at} می‌فرستد.
  3. کاربر دکمه را می‌زند ⇐ POST actions/<id>/confirm/ (بدنه‌ی دلخواه، مثلاً ردیف‌های تیک‌خورده).
  4. هسته داخل تراکنش: قفل ردیف، مالکیت (۴۰۳)، idempotent (اجرای دوباره نتیجه‌ی قبلی را برمی‌گرداند)، وضعیت، مهلت.
  5. execute(user, action, params) داخل یک savepoint اجرا می‌شود.
  6. هسته وضعیت نهایی، زمان اجرا و نتیجه را ذخیره می‌کند.

قرارداد خروجی execute#

خروجیاثر
{"status": "confirmed" | "partial" | "failed" | "cancelled", "message", "results": [...], "status_code": 200}اقدام نهایی می‌شود؛ results در action.result ذخیره می‌شود
{"error": "...", "status_code": 400} (بدون status)درخواست رد می‌شود ولی اقدام pending می‌ماند (مثلاً پارامتر نامعتبر)
استثناهسته آن را ممیزی می‌کند، اقدام failed و پاسخ ۵۰۰؛ هیچ تغییر نیمه‌کاره‌ای نمی‌ماند
Python
from agent_helper import actions
from agent_helper.plugins import ActionKind


def execute_cancel(user, action, params):
    order = Order.objects.select_for_update().filter(id=action.payload['order_id'], user=user).first()
    if order is None or order.status != 'open':                 # دوباره بررسی کن
        actions.audit(user, action, 'failed', 'سفارش دیگر باز نیست', node_id=action.payload['order_id'])
        return {'status': 'failed', 'message': 'سفارش دیگر قابل لغو نیست.',
                'results': [{'status': 'failed'}], 'status_code': 200}
    order.status = 'cancelled'
    order.save(update_fields=['status'])
    actions.audit(user, action, 'confirmed', 'لغو سفارش', node_id=order.id, amount=order.total)
    return {'status': 'confirmed', 'message': f'سفارش {order.id} لغو شد.',
            'results': [{'order_id': order.id, 'status': 'success'}], 'status_code': 200}


CANCEL_ORDER = ActionKind(
    kind='cancel_order',
    execute=execute_cancel,
    preview=lambda p: {'kind': 'cancel_order', 'order_id': p['order_id'], 'total': p['total']},
    propose_schema={'type': 'object', 'required': ['order_id']},
    audit_label='لغو سفارش',
)

ممیزی#

actions.audit(user, action, status, detail='', node_id=None, flow_id=None, amount=None)

node_id = شناسه‌ی مورد، flow_id = شیء والد، amount = مبلغ (همه اختیاری). برای هر مورد یک ردیف بنویسید.

from agent_helper import actions
action = actions.create_pending(request.user, conversation, 'cancel_order', {'order_id': 5, 'total': 1000})
event = actions.pending_event(action)      # همان رویداد SSE کارت
هرگز

در execute به params برای انتخاب کاربر یا شیء اعتماد نکنید؛ فقط زیرمجموعه‌ای از همان payload را بپذیرید (مثل ردیف‌های تیک‌خورده‌ای که در خود پیشنهاد بودند).
