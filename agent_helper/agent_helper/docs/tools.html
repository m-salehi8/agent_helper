ابزارها (ToolSpec)

تعریف ابزار، handler، رویدادها و ابزار پیشنهاددهنده

ToolSpec(name, description, json_schema, handler, read_only=True, proposes=None, tags=(), status=None, events=None, conversation_mode=None)
آرگومانتوضیح
nameنام یکتا ([A-Za-z0-9_-]، حداکثر ۶۴)
descriptionمتنی که مدل برای تصمیم به صدا زدن می‌خواند؛ دقیق و کوتاه بنویسید
json_schemaJSON schema آرگومان‌ها؛ باید {"type": "object", ...} باشد
handlerhandler(user, args, ctx) -> dict
read_onlyTrue برای خواندن. False یعنی پیشنهاد می‌سازد و حتماً proposes لازم است
proposesنوع اقدامی که این ابزار پیشنهاد می‌دهد
tagsبرچسب‌های موضوعی برای انتخاب ابزار؛ ابزار بی‌برچسب همیشه فرستاده می‌شود
statusمتن (یا callable(args)) رویداد tool_status
eventscallable(result) -> [event, ...] رویدادهای SSE اضافه (مثلاً جدول)
conversation_modeاگر None نباشد قبل از اجرا conversation.mode را تنظیم می‌کند

handler#

handler(user, args: dict, ctx: ToolContext) -> dict
  • user: کاربر احرازشده‌ی درخواست؛ هرگز از آرگومان‌ها نیست.
  • args: آرگومان‌های مدل (همیشه dict؛ ممکن است ناقص یا اشتباه باشد — اعتبارسنجی کنید).
  • ctx.conversation: گفتگوی جاری (یا None در اجرای مستقیم).
  • ctx.propose(kind, payload, minutes=None): ساخت اقدام معلق؛ هسته کارت را خودش می‌فرستد.

خطا را با {"error": "..."} برگردانید تا مدل به کاربر توضیح دهد؛ استثنای بدون مدیریت به خطای عمومی تبدیل می‌شود.

Python
def get_order(user, args, ctx):
    try:
        order_id = int(args.get('order_id'))
    except (TypeError, ValueError):
        return {'error': 'order_id باید عدد باشد.'}
    order = Order.objects.filter(id=order_id, user=user).first()   # همیشه محدود به user
    if not order:
        return {'error': 'سفارش پیدا نشد یا متعلق به شما نیست.'}
    return {'id': order.id, 'status': order.get_status_display(), 'total': order.total}


GET_ORDER = ToolSpec(
    name='get_order',
    description='جزئیات یک سفارش خود کاربر با شناسه',
    json_schema={'type': 'object', 'properties': {'order_id': {'type': 'integer'}}, 'required': ['order_id']},
    handler=get_order,
    tags=('orders',),
    status=lambda args: f'در حال دریافت سفارش {args.get("order_id")}...',
)

رویدادهای اختصاصی#

برای اینکه رابط کاربری جدول یا کارت نشان دهد، از events استفاده کنید. نام رویداد آزاد است؛ کلاینت باید آن را بشناسد.

Python
def _orders_event(result):
    if not result.get('orders'):
        return []
    return [{'event': 'order_list', 'items': result['orders'], 'count': len(result['orders'])}]

ToolSpec('list_orders', '...', SCHEMA, list_orders, events=_orders_event)

ابزار پیشنهاددهنده#

Python
def propose_cancel(user, args, ctx):
    order = Order.objects.filter(id=args.get('order_id'), user=user, status='open').first()
    if not order:
        return {'error': 'سفارش باز با این شماره ندارید.'}
    action = ctx.propose('cancel_order', {'order_id': order.id, 'total': order.total})
    return {'status': 'ready', 'action_id': action.id,
            'message': 'پیش‌نویس لغو آماده است؛ به کاربر بگو دکمه را بزند. هرگز نگو لغو شد.'}

ToolSpec('propose_cancel', 'پیش‌نویس لغو یک سفارش باز (لغو نمی‌کند)', SCHEMA, propose_cancel,
         read_only=False, proposes='cancel_order', tags=('orders',))
گفتگوی چندمرحله‌ای

برای فرم‌هایی که چند نوبت پرسش و پاسخ دارند، conversation_mode='create' (یا هر نام دیگر) بدهید. تا وقتی حالت خالی نشده، پیام‌های کوتاه کاربر («۲۵ آبان») به مسیر سریع نمی‌روند. ابزارهای دیگر با conversation_mode='' حالت را پاک می‌کنند و اقدام با resets_mode=True بعد از اجرای موفق.
