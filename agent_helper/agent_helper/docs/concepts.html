مفاهیم و معماری

مسیر یک پیام، اجزای قرارداد افزونه، مدل‌های داده و وضعیت‌های اقدام

مسیر یک پیام#

  1. ورود: POST chat/ با کاربر احرازشده؛ سقف نرخ (دقیقه‌ای/روزانه)؛ ذخیره‌ی پیوست تصویر اگر هست.
  2. تصویر: اگر پیوست دارد، مدل بینایی اطلاعات را استخراج می‌کند و متنش به پیام اضافه می‌شود (مسیر سریع کنار می‌رود).
  3. مسیر سریع: اگر روشن باشد: حالت گفتگو، regex مسیرها، یک فراخوانی مدل سبک، سپس مسیرهای افزونه‌ها. فقط با اطمینان ≥ آستانه پاسخ می‌دهد.
  4. حلقه‌ی LLM: سابقه‌ی گفتگو + ابزارهای مرتبط + پرامپت ساخته‌شده از قطعه‌ها؛ مدل ابزار صدا می‌زند تا پاسخ نهایی (حداکثر ۶ دور).
  5. رویدادها: هر مرحله SSE می‌شود؛ پیشنهادها کارت pending_action می‌سازند.
  6. اجرا: فقط وقتی کاربر دکمه را بزند: POST actions/<id>/confirm/.
  7. لاگ: یک ردیف لاگ درخواست + لاگ هر مدل و هر ابزار.

اجزای قرارداد افزونه#

جزءنقشصفحه
Pluginبسته‌ی همه‌ی اجزای یک افزونه؛ با agent_helper.register ثبت می‌شودنوشتن افزونه
ToolSpecابزاری که مدل یا مسیر سریع صدا می‌زند؛ فقط خواندن یا پیشنهادابزارها
ActionKindنوع اقدام معلق: پیش‌نمایش کارت و اجرای واقعیاقدام معلق
FastRouteمسیر بدون LLM (regex، سؤال بله/خیر، سؤال‌های اصلی)مسیر سریع
CatalogProviderموجودیت‌هایی که کاربر با نام صدا می‌زندمسیر سریع
PromptFragmentقاعده‌ی پرامپت؛ می‌تواند قاعده‌ی هسته را جایگزین کندپرامپت

مدل‌های داده#

مدلکاربرد
AssistantConversation (نام دیگر: Conversation)گفتگوی هر کاربر؛ mode = حالت گفتگوی چندمرحله‌ای
AssistantMessage (Message)پیام‌های user / assistant؛ محتوا JSON (متن و مسیر پیوست)
PendingActionاقدام معلق: kind، payload، status، expires_at، result
ActionAuditLogممیزی هر اجرای واقعی: کاربر، اقدام، شناسه‌ی مورد، وضعیت، توضیح
AssistantRequestLog (RequestLog)یک ردیف برای هر پیام: مسیر، دلیل، نیت، تعداد فراخوانی‌ها، توکن، مدت
ModelCallLogهر فراخوانی مدل (intent / chat / vision)
ToolCallLogهر اجرای ابزار با آرگومان و خلاصه‌ی نتیجه

وضعیت‌های اقدام معلق#

وضعیتمعنی
pendingمنتظر دکمه‌ی کاربر (پیش‌فرض ۱۰ دقیقه)
confirmedاجرا شد
partialبخشی از موارد اجرا شد
failedاجرا ناموفق (یا اجراکننده خطا داد)
cancelledکاربر لغو کرد یا هیچ موردی انتخاب نشد
expiredمهلت گذشت؛ دیگر قابل تایید نیست

اصول طراحی#

  • هوش مصنوعی پیشنهاد می‌دهد، انسان اجرا می‌کند.
  • همه‌چیز در محدوده‌ی کاربر جاری.
  • اول ارزان و سریع، بعد هوشمند؛ جواب غلط قطعی بدتر از جواب کند است.
  • قابل ردیابی: هر تصمیم و فراخوانی لاگ می‌شود.
