API و رویدادهای SSE

endpointها، بدنه‌ها، کدهای وضعیت و همه‌ی رویدادهای استریم

همه‌ی endpointها IsAuthenticated هستند و با کلاس‌های احراز هویت DRF پروژه‌ی شما کار می‌کنند (JWT، session، توکن). مسیرها نسبت به جایی‌اند که agent_helper.urls را include کرده‌اید (در مثال‌ها /api/assistant/).

روشمسیرنام URLکار
POSTchat/assistant_chatارسال پیام؛ پاسخ استریم SSE
GETconversations/assistant_conversationsگفتگوهای کاربر
GETconversations/<id>/assistant_conversation_detailیک گفتگو با پیام‌ها
POSTactions/<id>/confirm/assistant_action_confirmاجرای اقدام معلق
POSTactions/<id>/cancel/assistant_action_cancelلغو اقدام معلق

POST chat/#

فیلدنوعتوضیح
messagestring، اجباری، حداکثر ۵۰۰۰متن کاربر
conversation_idint، اختیاریادامه‌ی گفتگوی قبلی (فقط گفتگوی خود کاربر؛ وگرنه ۴۰۴)؛ خالی = گفتگوی جدید
imagedata URL، اختیاریتصویر png/jpg/webp (پیوست تصویر)
HTTP
POST /api/assistant/chat/
Authorization: Bearer eyJ...
Content-Type: application/json

{"message": "سفارش‌های باز من را نشان بده", "conversation_id": 12}

پاسخ 200 text/event-stream است؛ هر رویداد یک خط data: <JSON> و یک خط خالی. هدرهای Cache-Control: no-cache و X-Accel-Buffering: no برای عبور از nginx بدون بافر تنظیم می‌شوند.

وضعیتوقتی
200استریم (حتی خطای LLM به‌صورت رویداد error می‌آید)
400بدنه‌ی نامعتبر (JSON خطای DRF)
401بدون احراز هویت
404conversation_id مال کاربر نیست
429سقف دقیقه‌ای/روزانه یا تصویر نامعتبر؛ یک رویداد error با پیام فارسی

رویدادهای SSE#

eventفیلدهاکاربرد در UI
tool_statusstatusنوار وضعیت («در حال …»)
tokentextمتن پاسخ (فقط متن نهایی؛ متن قبل از فراخوانی ابزار نمایش داده نمی‌شود)
pending_actionaction_id، expires_at + فیلدهای previewکارت تایید/لغو
attachment_datadata، warningکارت «خوانده‌شده از تصویر»
doneconversation_id، message_id، path (fast یا llm)پایان؛ شناسه‌ی گفتگو را نگه دارید
errormessage (+ detail در DEBUG)هشدار
رویدادهای افزونهآزاد (از ToolSpec.events)جدول، کارت وضعیت، …
data: {"event": "tool_status", "status": "در حال جستجوی سفارش‌ها..."}

data: {"event": "order_list", "items": [{"id": 5, "total": 120000}], "count": 1}

data: {"event": "token", "text": "یک سفارش باز دارید."}

data: {"event": "done", "conversation_id": 12, "message_id": 88, "path": "fast"}

POST actions/<id>/confirm/#

بدنه‌ی دلخواه (JSON) که بی‌تغییر به ActionKind.execute به‌عنوان params داده می‌شود.

HTTP
POST /api/assistant/actions/45/confirm/
{"node_ids": [1024, 1031], "unchecked": "keep"}

200 {"message": "۲ مورد تأیید شد.", "action_id": 45, "status": "confirmed",
     "results": [{"node_id": 1024, "status": "success", "detail": "..."}]}
وضعیتبدنه
200نتیجه‌ی اجرا؛ تایید دوباره: {"already_confirmed": true, "status", "results"}
400{"error"}: منقضی، وضعیت غیر pending، نوع ناشناخته یا پارامتر نامعتبر
403اقدام مال کاربر دیگری است
404اقدام وجود ندارد
500اجراکننده خطا داد؛ اقدام failed و ممیزی شد
